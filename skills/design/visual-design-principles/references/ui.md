# 把印刷设计原则用于 UI

本文件是基于原书原则的转用建议，不是书中已有的 UI 规范。原书没有提供完整的交互、响应式、无障碍或组件工程方法。

## 先服从真实产品

阅读现有页面、组件和样式约定。找出当前任务要改善的阅读或操作问题，不为使用本 Skill 另起一套设计系统。

区分三个目标：营销页吸引并引导，内容页支持阅读，工作界面支持查找与操作。不要把海报式大标题和强对比焦点作为所有界面的默认结构。

改视觉不意味着可改流程、删数据、隐藏次要功能或替换业务规则。为解决布局而改变内容时，确认在用户授权范围内。

## 常见组件中的关系

| 场景 | 应当维护的关系 | 常见失败与最小修正 |
|---|---|---|
| 表单字段 | 标签、输入、帮助和错误属于同一个字段 | 帮助文字更靠近下个字段；调整字段内部结构与组间距 |
| 设置组 | 组标题和描述属于一组；行内标签与开关对应 | 每行都包大卡片反而拆碎同组内容；先调整行距与组距 |
| 列表与卡片 | 名称、摘要、元数据、动作有一致顺序 | 每条信息位置不同；复用结构，并处理不同文本长度 |
| 数据表 | 行表达记录，列表达同一属性 | 为全左对齐而破坏数值比较；数值可以按数位或右边界对齐 |
| 详情页 | 页面级行动与局部行动作用域不同 | 每一区都有同样醒目的按钮；按真实作用域区分 |
| 仪表盘 | 全局概览与各区域内部层级分明 | 把所有指标放大，或强制整屏只有一个焦点；先确定查找任务 |
| 营销首屏 | 标题、解释、行动形成连续路径 | 插图和按钮被大块空白隔开；重排组间关系 |
| 导航与内容 | 导航规则稳定，当前位置可辨 | 为避免重复而每页换样式；保持壳层和选中语义 |

卡片、分隔线、底色都可以表达真实边界。选择能让组关系清楚的最少手段，不一律禁用。滚动区域、点击范围、独立记录等可能需要明确容器，即使纸面广告不需要。

## 用结构维护对齐

用项目已有的布局系统表达共同列边、容器内边距与对齐基准。避免用空格、空行、文本长度或大量一次性位置补丁凑对齐。

视觉组通常应有对应的结构归属；同角色使用同一已有样式。只在重复确实存在且复用有价值时抽出组件或 token，单页微调不需要新建完整抽象。

检查图标的可见大小与文字基线，而不只看图标外框。来自同一图标集也可能需要少量光学校正。不要为了同尺寸而把不同含义的图标换成错误图形。

## 响应式保留关系，不保留海报坐标

屏幕变窄时可以重排列，但应维护信息的阅读顺序和所属关系：

- 标签、帮助、错误不要脱离字段；图注不要脱离图片。
- 桌面右对齐的短文可以在移动端转为左对齐，只要组关系和阅读顺序更清楚。
- 联系方式不要被插图隔断；主要行动不要因固定高度被裁掉。
- 文字变长或换行后，不能依靠单行文本高度维持脆弱对齐。
- 页面视觉顺序与键盘、辅助技术读取顺序应合理一致。

按实际内容出现问题的位置确定需要检查的视口，不为每个小改动穷举设备。至少查看交付要求中的尺寸，以及本次变更容易破坏的窄宽情况。

## 状态与可用性

已有状态应保持可辨。涉及字段、按钮或列表时，检查受改动影响的错误、选中、禁用、加载、空内容或长内容状态；不要求每次新增所有状态。

不要为降低视觉重量隐藏标签、移除焦点指示、缩小有效操作区，或让错误只剩颜色变化。必要的重复说明不属于应当删除的视觉噪声。

## 根据交付物选工具

- 可运行界面：在原项目中实现，使用真实渲染或浏览器查看。代码检查可确认共用样式，视觉检查确认实际结果。
- 设计稿：在可编辑布局工具中维护文字与图形；检查导出后的画面，避免编辑器和导出结果不一致。
- 图片：用户明确要图片时使用图片工具。生成提示应说明信息组、锚点、层级和精确文案。收到结果后逐项核对，不以提示词代替验收。

不要把可点击界面交付成一张图片，也不要未经请求把用户要的图片替换成网页。工具无法精确实现关键要求时，清楚报告未完成项；需要换交付类型时再取得相应确认。

## 验证范围

视觉微调通常需要实际尺寸截图、内容核对与相关状态检查，不需要为了改间距新增单元测试。只有改动行为或存在明确回归风险时，运行相应检查或添加有必要的测试。完成项目要求的检查，不以截图替代行为验证。
