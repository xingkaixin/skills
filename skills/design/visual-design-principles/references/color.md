# 颜色：先指定用途，再指定色值

依据：原书第 7 章、第 12 章的颜色与文字密度讨论。UI 语义与验收为转用建议。

## 选择起点

优先使用已有品牌或设计系统的颜色。新方案可从主图、产品或内容主题中取得基础色，再确定正文、背景、分组、强调等角色。不要在结构不清楚时先更换整套配色。

| 关系 | 原书中的用途启发 | 使用时的判断 |
|---|---|---|
| 单色及其深浅变化 | 用较少色相保持统一 | 深浅能否区分角色，文字是否足够清楚 |
| 类似色 | 相邻色形成连续、协调的感觉 | 会不会因为明暗接近而难以区分 |
| 互补色 | 不同方向的颜色产生鲜明差异 | 通常应有主次，不必面积各半 |
| 三色组 | 多色之间形成联系 | 不等于每一种颜色都必须突出 |
| 分裂互补 | 在对比与协调之间形成另一种选择 | 根据画面结果选择，不因几何关系自动认定好看 |

书中的色轮是绘画与印刷教学的简化工具。不要把颜料混色规则直接当作 RGB 数值计算方法。

## 三个经常被遗漏的变量

**明暗。** 色相不同但明暗接近，前景和背景仍可能难读。先改变明暗关系或背景，再考虑描边、阴影等额外处理。

**面积。** 少量强调色和铺满整页的同一种色，效果不同。增加强调色的使用次数或面积，会让多个区域互相竞争。

**环境。** 相同颜色放在不同背景、图片与邻近颜色旁边，视觉效果会变化。必须检查实际组合，不能只看调色板。

原书描述暖色前进、冷色后退，可作为观察方向；不能据此断言所有暖色按钮都比冷色醒目。亮度、饱和度、尺寸和周围空间同样影响注意力。

## 在 UI 中分开两件事

品牌配色用于建立识别；状态配色用于告诉用户成功、警告、错误、选中等含义。两者可以有关联，但不能为重复品牌色而消除状态差别。

选择和错误不能只靠颜色表达；同时提供适当文字、形状或状态标记。次要文字需要降低竞争，不应低到无法阅读。装饰色可低对比，不等于功能文字也可同样处理。

灰度观察可帮助诊断层级，但不能替代文字、控件和焦点状态的对比检查。若需声明符合某个无障碍标准，按项目要求核对该标准与实测结果；这本书不提供完整合规依据。

## 输出检查

在正常展示尺寸检查标题、正文、背景、图片和强调元素的组合。深色背景上的反白小字尤其要确认笔画和间距。

屏幕交付关注实际像素尺寸、色彩空间与显示结果。印刷交付按供应商要求处理色彩配置和打样，见 [媒介与印刷](print.md)。不要反复转换色彩空间，也不要假设屏幕中的颜色会在纸上原样重现。
